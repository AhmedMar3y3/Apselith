# Performance

The initial renderer defaults to CelesTrak's stations group. Starlink, operational GPS, Galileo and weather groups load on demand. Full catalogs remain searchable, while a stable subset of up to 150 matches, including the selected object, is propagated and rendered. The catalog list reveals 60 rows at a time. Catalog markers use a billboard collection with shared SVG textures; only the selected object gets a sampled trajectory. SGP4 work occurs in a worker and React does not drive Cesium's per-frame loop. A persistent selected label avoids entity recreation during motion. The 150-object guardrail is not a benchmark or a claim that rendering all Starlink objects has been validated.

Worker buffers refresh at roughly one wall-clock second, with coverage adapting to playback speed. Ten-second position/velocity samples feed cubic Hermite interpolation at the current clock time, capped at 30 render updates per second or four for reduced-motion preferences. Trajectories refresh on simulation-minute boundaries. No out-of-buffer extrapolation is performed. Hidden tabs stop clock notifications, propagation submissions and render updates. A maximum device-pixel ratio of 1.5 limits rendering cost on dense displays. Software-rendered Chromium struggled with continuous 30 Hz rendering during tests; browser workflow tests use the actual reduced-motion mode. Hardware performance remains unmeasured.

Cesium is a separate lazy-loaded chunk. The first measured successful production build produced a globe JavaScript chunk of approximately 4.17 MB (1.12 MB gzip); this remains substantial and Vite emits a size warning. The app shell and laboratory do not eagerly import Cesium. Further optimization must preserve required renderer features rather than hiding the warning.

No representative hardware benchmark has yet been completed. Do not infer FPS, memory, catalog capacity or time-to-interaction from a successful build. The master plan's 100/1000/5000/10000-object runs remain required before expanding the default rendering scope. Use real public element datasets, document hardware/browser/version and whether a software or hardware GPU was used. Never duplicate a single satellite and call that a realistic catalog benchmark.

Sun bloom, high dynamic range and FXAA are disabled to reduce rendering cost. Detected software renderers use a 0.65 resolution scale and a 12 FPS Cesium target; accelerated graphics retain the capped device-pixel resolution and 30 FPS target. Reduced-motion interpolation remains capped at four updates per second. Renderer detection stays local. These settings are targets, not measured hardware performance. Planet ephemerides refresh once per simulation minute; their cached vectors are projected into the camera view each rendered update.
